# Decisions Log

## Phase 3 + 4 (this build)

### Verified (actually tested, not assumed)
- Postgres 16 + pgvector installed and run locally (via apt, since Docker was unavailable
  in the build environment) to test migrations against a real database, not just generate
  SQL and hope.
- `alembic upgrade head` on a clean DB: all 17 tables, indexes, FKs, and the pgvector
  `vector(1536)` column created correctly.
- `alembic downgrade base` → `upgrade head` cycle run twice successfully.
- Found and fixed: missing `pgvector.sqlalchemy` import in autogenerated migration
  (autogenerate doesn't always add type imports for extension types).
- Found and fixed: `CREATE EXTENSION vector` was not part of the migration — added
  explicitly so a fresh environment doesn't depend on manual setup.
- Found and fixed: SQLAlchemy `Enum()` defaults to storing Python enum member *names*
  (`USER`) not `.value` (`user`) — added `values_callable` to every enum column and
  verified with a live insert that the DB now stores lowercase values matching the
  intended API contract.
- Found and fixed: Alembic downgrade doesn't drop Postgres ENUM types when their owning
  table is dropped, leaving orphaned types that break a subsequent `CREATE TYPE` on
  re-upgrade. Added explicit `sa.Enum(...).drop()` calls to `downgrade()`, verified.
- Verified `ck_citation_exactly_one_source` CHECK constraint actually rejects an invalid
  citation row (both source columns NULL) with a live INSERT attempt.
- FastAPI app boots and `/health` returns 200 (smoke test).

### Not verified (written but untested — flagged, not silently assumed complete)
- `docker-compose.yml` / `Dockerfile` — no Docker daemon available in the build sandbox.
  These follow standard, well-tested patterns (pgvector official image, standard uvicorn
  Dockerfile) but **have not been run end-to-end**. Needs verification on a machine with
  Docker before being trusted for onboarding.
- pgvector index strategy (ivfflat vs. hnsw, list/ef parameters) — not configured. No real
  embedding volume exists yet to tune against; deferred to Phase 8 per the build plan.
- Performance under concurrent load / realistic data volume — not tested at this stage.
